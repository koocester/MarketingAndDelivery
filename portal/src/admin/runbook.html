Portal Operations Runbook

How to run and maintain the staff portal without needing Claude. Any developer or future AI can pick it up from this page.

🛡️ Founder only

1What it is

The portal is a set of plain HTML files (no framework, no build step) hosted on Cloudflare Pages. Staff sign in with their @koocester.com email (a 6-digit code, no password), and land on a tile hub. Some tiles show only to managers, and the Admin section only to you.

3Redeploy after an edit

From a terminal inside the Training folder:

npx wrangler pages deploy . --project-name koocester-academy --branch main --commit-dirty=true

No terminal? Cloudflare dashboard → Workers & Pages → koocester-academy → Create deployment → drag the folder in. Always open the portal afterwards and refresh once to confirm.

4Add or remove a staff member

Staff are a roster in Supabase; new people auto-create on first sign-in. Supabase → SQL Editor:

insert into public.roster (email, full_name, department, role, is_admin) values
  ('newperson@koocester.com','Full Name','Department','Role',false)
on conflict (email) do update set
  full_name=excluded.full_name, department=excluded.department,
  role=excluded.role, is_admin=excluded.is_admin;

To remove access, delete them in Supabase → Authentication → Users.

5Make someone a manager

Either set is_admin=true on their roster row, or add their role to MANAGER_ROLES at the top of portal.html (also update manager/koo-manager-guard.js). Redeploy.

The gate is soft. It hides tiles and bounces the normal flow, but a management file is still fetchable by URL past the shared password. For hard per-user security, turn on Cloudflare Access (Zero Trust → Access → email policy). Keep raw financials and individual pay out of tiles until then.

6Add or edit a tile

Open portal.html, find the SECTIONS array. Each tile is one line: icon, title, desc, href, status ('live' or 'soon'), access ('all'/'manager'/'admin'), optional external:true. To turn a "Coming soon" tile live, set its real href and change status to 'live'. Redeploy.

7Post a "What's New" update

Sign in as yourself, open the bell, click ＋ Post. Pick a kind (Update / Announcement / Training). For a training rollout set the link to the Academy deck, so staff jump straight in to complete it. The unread badge clears per person as they open each item. (One-time setup: run announcements-schema.sql in Supabase.)

8Rotate the shared password

Edit functions/_middleware.js (USER / PASS), redeploy, tell the team.

9How the login works

Person enters email → Supabase emails a 6-digit code → they type it → in. The code works on whatever device typed it (that is why we use a code, not a link). For the code to appear in the email, the Supabase Magic Link template must contain {{ .Token }}. Emails go through Resend; if they stop arriving, check the Resend dashboard first.

10If AI is gone tomorrow

  • The site is plain files in Git. Any web developer edits them.
  • Cloudflare and Squarespace are point-and-click; this page covers the actions.
  • Supabase is standard PostgreSQL. Export via Database → Backups any time.
  • Resend is standard email; swappable in the Supabase SMTP settings.
  • Accounts to keep: Cloudflare, Supabase, Resend, Squarespace.

Hand this page (or the full PORTAL-OPERATIONS-RUNBOOK.md in the Website-Revamp project) to any developer and they can run the whole system.
