**Item 4 — WORSE than the audit says, and it is a v5 REGRESSION, not a pre-existing gap.**
The v1 deck carried **2** `APPROXIMATE` registry markers and 26 `<p class="source">` paragraphs.
The shipped v5 deck carries **0** and 5. The V5 Transform caption-prune drops every source paragraph

  SG ~79k low on 7 Aug;

  never quote a conversion rate from these").

Root cause: Faiz's rule bans *explainer* captions ("What this says", fact-pack stamps, footer source

the rule — governance caveats are not explainers.

**Fix (V5 Transform, caption-prune pass):** keep a `<p class="source">` when it carries a governance
marker — `APPROXIMATE`, `Metric Registry`, `not fully accurate`, `Broken` — and strip only the
explainer prose from it. Today the pass keeps a paragraph only if it contains `cchip`.

Hakim's Claude asked whether the numbers are **true and complete against source**. Both findings

## APPLIED (round 2) 2026-08-08 — items 2, 3, 5, 8, and the archive that never ran

### The deck was NOT in Staff Academy at all
The Sat 08:45 archive (execution 54760) **errored**: `there is no unique or exclusion constraint
matching the ON CONFLICT specification`. `reports_kind_dated_uidx` is a PARTIAL unique index
(`WHERE kind IN ('weekly','townhall','mediakit')`), almost certainly narrowed so the repeated
`weekly_manager_edit` scratch rows dated 2026-01-01 could coexist. `ON CONFLICT (kind, dated)`
cannot match a partial index without repeating its predicate, and Postgres rejects it at plan time.
Not caused by the 7 Aug archiver edit — that only touched jsonb metadata values.

**Fix:** conflict target is now
`ON CONFLICT (kind, dated) WHERE kind IN ('weekly','townhall','mediakit') DO NOTHING`,
verified against the live index before applying. Re-ran the weekly branch only — the `WH Archive Now`
webhook fans out to Townhall too, and Prep Townhall would have written `dated=2026-08-01` against an
existing August row dated `2026-08-04`, i.e. a **duplicate town hall**. Fan-out restored afterwards.

### Item 8 — the dead overdue column, confirmed and fixed
The audit was right and an intermediate reading here was wrong. `Overdue` returns
`{"type":1,"value":[{"text":"OVERDUE"}]}`; `String()` on that is `[object Object]`, so
`.includes('OVERDUE')` never matched and all 1,609 rows wrote `false`. Sampling two non-overdue
records first made it look like an empty field — it is not, 125 records carry the value.
**Fix:** `overdue: String(txt('Overdue')||'').includes('OVERDUE')`, reusing the node's existing
`txt()` helper which already handles that shape. Re-ran the extract:
**1,610 rows, 125 overdue** — matching the deck and Lark exactly. Was 0.
