# Weekly slides — Faiz's independent audit, 2026-08-08

Faiz re-ran ~40 figures against Xero, HubSpot, Metricool, `team_throughput` and the Lark base after
the first v5 deck went to managers (Sat 08:50 / 09:00 sends). **Verdict: the deck is fundamentally
trustworthy.** Engagement across all three windows, posts, views, followers to the digit, all four
role outputs with their WoW deltas, every cash figure, the project book, the funnel, HR and events
all match source. No Broken-registry metric is rendered anywhere, "not measured" is shown honestly
rather than as a fake zero, and the Metric Watchdog the deck claims (Sat 07:30) exists and is active.

Below is the fix queue, ranked as Faiz ranked it. **None of these are applied yet** — the n8n
connection dropped before they could be made. Each entry names the exact place to change.

## 1. "7 deals still open" is wrong — the only factually incorrect number
Live open deals = **20** (the S$34,684 value is correct). The `7` is the *new deals opened this week*
count wired into the wrong sublabel. Slide 6 therefore contradicts slide 7, which correctly sums 20.
**Fix:** in **Build Deck** (`t9ZZ7sk9hyWEKNdR`), the `sales` slide's "Open pipeline value" tile takes
its sub from `num(growth.deals)`. Point it at the open-deal count from the same query that feeds the
stage table (`wf.open_by_stage`), i.e. `sum(r.n)` — or relabel it "9 deals carry value".

## 2. "Where every video is sitting right now" omits 183 active videos
Shows 5 stages (717 total) but skips **Approval 92, Ready to Edit 54, Ready to Shoot 23, Final
Approval 12, Amendments 2** — buckets the deck's own team slides already display (editors "waiting
54", producers "booked 23"). A slide titled *every* video that misses ~a fifth of the active pipeline
is what staff will catch first. True active total ≈ **900**.
**Fix:** the stage list comes from `ops.pipeline` in the fact pack, not from the renderer — V5
Transform faithfully renders whatever rows it is given. Fix the source so it emits all active stages
per the registry's stage-count rule.

## 3. Strategist work-in-hand breaks its own registered rule
Registry: Strategists = Approval + QC + Planning + Amendments (Marketing) = **337**. Slide shows
**245**, omitting Approval (92).
**Fix:** add the Approval bucket — *or*, if Approval is deliberately the Head of Growth's queue now,
amend the registry rule so surface and rule agree. One or the other; they must not disagree.

## 4. Missing "Approximate" caveats the manifest already promises
Only the overdue tile carries the ≈. The **Network followers** slide has a registry-proven failure
mode (partial snapshots served SG ~79k low on 7 Aug) and the **contacts/customers** tiles are pending
CRM cleanup — the deck's own guard manifest declares both caveated, yet neither renders a caveat.
**Fix:** render the ≈ plus a one-line caveat on those tiles. The ≈ mechanism already exists in V5
Transform (`scorecard` pass) and can be reused.

## 5. The guard has blind spots — several rendered metrics are ungoverned
On the deck but **not in the manifest**, some with no registry row at all: pipeline-by-stage value
(approved for Command dashboard only), weekly deals opened/won, weekly enquiries, the hiring funnel,
headcount, weekly engagement, and the book-progress rule. The numbers verified correct, so this is
**governance debt, not bad data** — but the guard cannot catch what is not declared.
**Fix:** add/extend the registry rows and their Appears-on surfaces, then regenerate the manifest.
**Better:** generate the manifest *from* the deck build so the two cannot drift.

## 6. "No QC-passed timestamp yet" is stale — the deck contradicts itself
`QC Passed At` and `Storyboard Done At` have existed since 5 Aug (stamped by the Approve QC button),
and the roadmap slide correctly says "done 100%" — while slides 10/14 still say the timestamp does
not exist.
**Fix:** update the two slide texts ("stamp live since 5 Aug — first full measured week lands next
week"), switch the throughput job to count QC passes, update the registry rows. Note the strategist
row in marketing-summary reads "not measured" for the same reason.

## 7. Role outputs miss Saturday, every week
The throughput snapshot runs **Sat 07:00** for a week that ends **Saturday night**. So role outputs
are frozen a day early while posts/views on the same deck are computed live over the full week.
**Fix:** add a **Monday 06:00** re-run — the job's `ON CONFLICT … DO UPDATE` makes reruns safe (this
is the same property that let the row be populated early on 7 Aug). Also correct the registry
wording: it still says "Monday to Sunday" and "Sundays 23:00"; the implementation is Sun–Sat,
snapshotted Saturday.

## 8. The warehouse mirror's `overdue` column is dead
All **1,609** rows in `video_contributors.overdue` read `false`. The deck's 125 is right (confirmed
exactly against Lark live), but the nightly extract flattens the formula — the same object-vs-string
parsing trap that bit the weekly report before. Any warehouse consumer of that column silently reads
zero.
**Fix:** `sel()`-style parsing in **Video Contributors Extract** (`YyEgA3gvW7Fpsxqw`).

## 9. Home Fair date conflict, upstream of the deck
The base (and therefore the deck) says **18 Sep**; the RSVP workflow is named **"Sep 19–20"**. One is
wrong and it cannot be adjudicated from the data. A manager who knows the real date will spot it.
**Fix:** events owner corrects the base record (start/end dates + attendance target); the deck
self-corrects on next render. Separately, "3 confirmed" overstates — two of those events are status
*Planning*.
